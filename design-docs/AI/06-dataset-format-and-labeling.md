# Dataset Format and Labeling Strategy

This document outlines how data is categorized, annotated, and formatted.

## Labeling Strategy

### 1. Label Sources
- **Human Labels**: Ground truth annotations created or verified by a human expert. Highest priority during training.
- **CV Pseudo-labels**: Generated purely by classical computer vision algorithms. Used to bootstrap early models.
- **AI Pseudo-labels**: Generated by a highly confident trained model. 
- **Active Learning**: The model flags low-confidence predictions, which are queued for a human to review. Once reviewed, they become Human Labels.

### 2. Review Workflow & Confidence Thresholding
Predictions from the AI or CV pipeline are scored.
- `Confidence > 0.95`: Automatically accepted as an AI Pseudo-label.
- `0.40 < Confidence < 0.95`: Sent to the Human Review Queue (e.g., in Label Studio).
- `Confidence < 0.40`: Discarded.

### 3. Object Classes
The dataset must account for more than just cells. Artifacts must be explicitly labeled so the model learns to ignore them.
- `RBC` (Red Blood Cell)
- `WBC` (White Blood Cell - can be sub-classed later)
- `platelet`
- `artifact` (sensor dust, scratches on the slide)
- `bubble` (air bubbles in the fluid)
- `debris` (unidentifiable biological matter)
- `unclear/ignore` (used by annotators when they cannot determine the class; the loss function should ignore these regions during training).

### 4. Handling Unlabeled & Image Quality Data
- **Unlabeled Data**: Kept in a separate directory for self-supervised pretraining (e.g., training a DINOv2 feature extractor).
- **Image Quality Labels**: A separate dataset containing whole-image labels: `sharp`, `blurry`, `overexposed`, `underexposed`, `empty`.

### 5. Locked Validation/Test Split
Data is split geographically/temporally (e.g., by slide, by cartridge, or by day), not randomly shuffled. Random shuffling leads to data leakage if adjacent stitched frames end up in both train and test sets.
The Test set is strictly locked and never used for hyperparameter tuning.

## Data Formats

- **Object Detection**: YOLO `.txt` format or COCO JSON.
- **Segmentation**: PNG Masks. We strictly separate detection labels from segmentation masks to allow training different models independently.

## Example Label Schema JSON (`label_schema.json`)

```json
{
  "version": "1.0",
  "classes": {
    "0": {"name": "RBC", "color": "#FF0000", "type": "polygon"},
    "1": {"name": "WBC", "color": "#00FF00", "type": "polygon"},
    "2": {"name": "platelet", "color": "#0000FF", "type": "polygon"},
    "3": {"name": "artifact", "color": "#FFFF00", "type": "bbox"},
    "4": {"name": "bubble", "color": "#00FFFF", "type": "polygon"},
    "5": {"name": "debris", "color": "#FF00FF", "type": "bbox"},
    "6": {"name": "unclear", "color": "#808080", "type": "polygon"}
  },
  "metadata_requirements": ["confidence", "source_type", "reviewer_id"]
}
```
